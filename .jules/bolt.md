## 2024-05-18 - String split_once vs split().collect()
**Learning:** `split().collect::<Vec<_>>()` forces full string scanning and an unnecessary O(N) heap allocation, while `split_once()` avoids the `Vec` entirely and stops at the first match. Similarly, `lines().collect::<Vec<_>>()` unnecessarily allocates memory when we can iterate directly over the lines iterator.
**Action:** When extracting parts from a string via delimiters or iterating lines, avoid `collect::<Vec<_>>()` if possible. Use `split_once()` for two-part splits and iterate directly on `lines()` to reduce memory overhead and improve processing speed in parsing-heavy logic like metadata and responses.
